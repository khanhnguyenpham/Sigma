Cách làm một task:

  2. Chọn một phần nhỏ: mục tiêu, file sửa, đầu ra, kiểm tra cần chạy.

  git status
  git switch main
  git pull --ff-only origin main
  git switch -c codex/t02-local-environment

Ví dụ commit/push SAU KHI đã tạo và kiểm tra các file môi trường:
  git add requirements.txt README.md
  git diff --cached
  git commit -m "T02: set up local environment"
  git push -u origin codex/t02-local-environment

requirements.txt hiện chưa tồn tại; đây là ví dụ cho phần kỹ thuật tương lai,
không phải lệnh đã chạy. Thay danh sách file bằng file thật của phần mình làm.
Các lần sau trên cùng nhánh: git add đúng file -> git diff --cached
-> git commit -m "mô tả thay đổi" -> git push.

Khi task xong, mở PR từ nhánh task vào main, ghi kiểm tra/kết quả và giới hạn.
Chỉ merge sau đủ kiểm tra. Nếu GitHub yêu cầu reviewer độc lập, phải tuân thủ
quy tắc repository; không tắt bảo vệ hoặc tự nhận đã được người khác duyệt.

8. XỬ LÝ LỖI THƯỜNG GẶP

Push bị từ chối do quyền/xác thực:
  Kiểm tra git remote -v, đúng tài khoản và đã chấp nhận lời mời collaborator.

Push bị từ chối vì nhánh remote có commit mới:
  Đảm bảo đã commit thay đổi local. Trên nhánh task có upstream, chạy:
    git pull --no-rebase
  Xử lý conflict nếu có, kiểm tra lại rồi git push. Không dùng push --force.

Merge conflict:
  1. Chạy git status để xem file xung đột.
  2. Trao đổi với người sửa cùng file để thống nhất nội dung cần giữ.
  3. Sửa từng đoạn có <<<<<<<, =======, >>>>>>>; bỏ các dấu conflict.
  4. git add từng file đã xử lý.
  5. git commit để hoàn tất merge, kiểm tra lại rồi git push.
  Nếu chưa thể giải quyết và merge vẫn đang diễn ra, có thể git merge --abort
  để hủy lần merge này. Chỉ bắt đầu merge khi đã commit sạch phần việc local.

File không được Git nhận:
  Kiểm tra git check-ignore -v DUONG_DAN_FILE.
  Không dùng git add -f để đưa dữ liệu riêng tư vượt qua .gitignore.
